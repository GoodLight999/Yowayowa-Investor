# Backtesting

## Strategy definitions

The backtest catalog is stored in `src/yowayowa/backtest_strategies.json` and validated as `BacktestStrategyDefinition`. Current built-ins are 12-1 momentum, low-volatility selection with inverse-volatility weighting, 20-session mean reversion, an equal-weight baseline, and supplied-input fundamental value / Kiyohara value rankings. Definition fields expose the signal, symbol universe, rebalance frequency, maximum holdings, weighting rule, and execution timing. The catalog is intentionally separate from the research `strategy_presets` catalog: a research checklist is not itself a trading signal. Fundamental rankings require explicitly supplied point-in-time financial inputs; this engine does not acquire or backfill financial histories.

## API and CLI

- `GET /v1/backtest/strategies`
- `POST /v1/backtest/run`
- `yowayowa backtest run --strategy <id> --start YYYY-MM-DD --end YYYY-MM-DD [--annualization-days 252]`

API/CLI runs use persisted daily stock OHLCV (Alpaca by default). The standalone `run_backtests_crypto.py` uses Binance crypto histories; `--data-dir` selects an existing store without moving or modifying its raw data. Rows are never sourced from live fetching during a run; missing histories fail closed or are reported insufficient. Costs default to 10 bps commission and 5 bps slippage on gross traded notional; both are request parameters. Bootstrap sample count and seed are explicit fields.

`annualization_days` is a validated integer request parameter (1–366). When omitted, the service request defaults to 252 for Alpaca and 365 for Binance. The stock CLI defaults explicitly to 252; the crypto runner explicitly requests 365. The effective value is returned at the response and metric-set levels (full-window, IS and OOS), including insufficient results. CAGR, Sharpe, Sortino, annual turnover, bootstrap CAGR intervals and Calmar all use that same convention. This is observation-count annualization: cash/warmup days and the first equity observation remain in the return sample. It is not elapsed-time annualization or a risk-free-rate-adjusted Sharpe.

## Persisted financial inputs and missing-data policy

`StockOhlcvRecord` and the existing JSONL `StockOhlcvStore.append/read` path preserve optional `disclosure_date`, `pbr`, `per`, `net_cash_ratio`, and `kiyohara_net_cash_ratio`. Old price-only rows remain usable; absent financial fields remain `None`, not zero. A financial input is eligible only when both its price-bar date and disclosure date strictly precede execution. The most recent eligible row supplies all financial fields together; incompatible rows are not joined to fill missing values. PBR/PER must be positive and every numerical input finite. Yowayowa's conservative cash ratio and the Kiyohara cash ratio remain separate fields; the engine never substitutes one for the other.

Missing, invalid or not-yet-disclosed inputs exclude the symbol from that decision. If no targets are eligible, the established policy is to retain current holdings (remain in cash before initial investment), not force liquidation. Warnings identify excluded symbols, reasons, affected rebalance date spans and decision counts, and explicitly identify no-target holding retention. A newer row without a valid disclosure date may leave an older disclosed row eligible; the missing latest disclosure is still warned. `status` describes metric availability, not complete financial coverage: consumers must inspect warnings. No historical EDINET/SEC enrichment or automatic finance join is implied by these supplied-input strategies.

## Crypto absolute-trend contract (S-01)

`crypto_trend_dual_ma` is an inline crypto-runner definition, not an entry in the stock strategy catalog: API/CLI stock stores cannot supply its Binance BTC/ETH data. `BacktestStrategyDefinition.lookback` is optional (`int | None`, default `None`, range 2–1000). This signal uses effective lookback `strategy.lookback or 200`; S-02 uses the distinct return-count convention below. Legacy signals and their warmup values are unchanged.

For each execution/decision session t, independently for every universe member, take the closes of sessions strictly before t. Fewer than lookback observations fail closed without forward-fill or imputation. Otherwise hold the asset only if `close(t-1) > mean(last lookback prior closes)` (SMA at t-1). Equality or a lower close means zero weight. This is an absolute trend gate, not a ranking or top-position selection: allocate equal active 1/N weights (BTC/ETH both active: 50/50; one active: 100%; none: 100% interest-free cash). Inactive assets are not assigned a residual fixed half-weight.

The signal always returns every universe symbol explicitly, with `0.0` for every inactive symbol, including an all-zero nonempty dictionary when all fail. This differs deliberately from the existing empty-target retention policy: an empty dictionary would retain old positions, so it must never be used for this gate. All-zero targets trigger liquidation, gross sell turnover, costs and previous-weight-to-zero trades through the existing execution loop. The runner configures `rebalance=daily` and `execution=next_open`: strictly lagged signals are evaluated every session before that session's open, never using its current or future close. Both warmup and IS/OOS purge use the effective lookback. Equal active weighting takes precedence over generic weighting/max-position ranking fields for this signal.

`run_sensitivity_crypto_trend.py --data-dir <existing-data>` reruns lookback 100/150/200/300 under the same costs, source and calendar and writes `crypto_trend_sensitivity.json`. It explicitly reruns the independent IS/OOS segments with bootstrap enabled to supply their IID intervals; the ordinary engine response keeps its existing IS/OOS-bootstrap-disabled contract. Cash-shift counts are taken from lagged target weights, not inferred from daily trades (which also contain price-drift rebalancing).

## Defensive-sector rotation contract (S-05)

`defensive_rotation` is an inline definition in `run_backtests_defensive_rotation.py`, not a new stock API catalog entry. The normalized universe must contain SPY. There are no additional model fields. Using only bars strictly before execution t, risk-on is `(SPY[-1]/SPY[-21]-1 > 0) AND (SPY[-1] > mean(SPY[-100:]))`. Equality, fewer than 100 prior closes, or invalid gate inputs fail closed to risk-off. At each configured rebalance, risk-on ranks all universe assets by `closes[-22]/closes[-253]-1` (253 prior closes required), descending score with ascending-symbol ties, taking five at fixed 20% each. Missing growth slots stay in cash. Risk-off ranks only JNJ/PG/XOM/JPM intersected with the universe by sample standard deviation of their last 60 session returns (61 closes), ascending sigma with ascending-symbol ties; up to three selected assets share equal 1/N, even if fewer than three qualify. Non-finite sigma or invalid/incomplete inputs are excluded; no forward-fill or other imputation occurs.

Both sleeves bypass generic weighting/max-position fields and always return all universe symbols explicitly: nonselected assets have 0.0 and zero candidates means full liquidation, not empty-target holding retention. There is no leverage; residual cash is interest-free USD. Execution math is unchanged. Warmup/purge is fixed at 253 sessions; this purge does not forbid the defensive sleeve from trading once its shorter 61-close requirement is met.

The S-05 runner uses persisted Alpaca SPY/QQQ/IWM/JNJ/PG/XOM/JPM/AAPL/MSFT/NVDA, monthly primary and a full daily re-selection A/B variant, plus same-universe monthly momentum (five), inverse-volatility low-vol (five), and equal-weight (ten) baselines. It writes `backtest_results_s05.json` with full/IS/OOS metrics, independently rerun segment bootstrap intervals (1000, seed 20260930), scheduled decisions, carried sleeve vs hypothetical daily R, observed defensive intervals, switch/session counts and zero-cost rerun CAGR drag. All five reported OOS segments use a shared 253-session purge and independent cash initialization; legacy engine-native low-vol/EW purge remains 61/0 and its differing OOS date is separately disclosed. Daily A/B rebalances the full strategy each session, not only an emergency one-way exit. Initial entry is excluded from switch counts; a switch-day return still includes prior-sleeve overnight P&L. The fixed universe differs from P3; CIO -6.60% OOS CAGR / -34.64% full MaxDD are external references only, not the main acceptance baseline. Price basis for the tracked artifacts is raw persisted bars with the seven SEC split-calendar events applied (dividends excluded); OOS numbers are identical under both bases. The mandatory same-universe drawdown criterion passes under the split-only basis (-22.01% vs -25.13%) but fails again under the dividend-inclusive TR basis (G1 `results_v6`), so the strategy remains rejected on the TR evaluation. See `BACKTEST_REPORT_S05_DEFENSIVE_ROTATION.md` for the basis-dependent verdict and limits.

## GARP momentum / PBR hybrid contract (S-03)

`garp_momentum_hybrid` is an inline definition in `run_backtests_garp_momentum_hybrid.py` with display name `GARP: momentum with PBR filter`, not an API catalog entry. It reuses existing `pbr` and `disclosure_date` inputs without new fields or an SPY requirement. For each scheduled decision t, require 253 prior closes, all required prices finite and positive, and rank `closes[-22]/closes[-253]-1` descending with ascending-symbol ties. Keep eight momentum candidates. Within those eight, rank valid point-in-time PBR ascending with ascending-symbol ties and take up to five. Both bar day and disclosure date must be strictly before t; the latest eligible bar supplies PBR, finite and strictly positive. A missing/invalid PBR in that bar is not filled from older rows. A newer undisclosed bar is ineligible, so the latest older disclosed bar can still qualify, exactly as in supplied-input fundamental value. There is no finance-row join, forward-fill, zero fill or live acquisition.

With at least one valid PBR candidate, every selected asset receives fixed 1/5, even with fewer than five; residual weight is interest-free USD cash and generic weighting/max_positions are ignored. With zero valid candidate PBR and at least one momentum candidate, delegate to the unchanged `momentum_12_1` path with `max_positions` and equal weighting. GARP always expands the result to all universe keys with nonselected `0.0`. Fallback equality means exact weights/selected symbols after expanding momentum's omitted keys to zero, plus exact metrics, equity curve and trades in the execution engine, not equal dictionary key sets. No momentum candidates means explicit all-zero targets and liquidation, never empty-target retention. Momentum/PBR exclusions, no-candidate liquidation and fallback are reported through the existing aggregated financial-input warning format. No leverage; warmup/purge is 253 and legacy signals/execution are unchanged.

The runner uses persisted Alpaca AAPL/MSFT/NVDA/GOOGL/AMZN/META/TSLA/JPM/XOM/SPY and three monthly definitions: GARP (five), mandatory momentum baseline (five) and equal-weight reference (ten). All share the same price calendar, requested window, 10+5 bps costs, annualization 252, bootstrap 1000/seed 20260930 and 70% IS/shared 253-session-purged OOS; segments start independently in cash. EW's native engine purge remains zero and its native split is disclosed separately, while the reported reference OOS matches GARP. Full/IS/OOS bootstrap intervals are independently rerun, leaving the engine's native IS/OOS-bootstrap-disabled behavior unchanged.

`backtest_results_s03.json` records every segment's rebalance candidates, valid PBR candidates, selected symbols, explicit targets, fallback state, per-symbol PBR coverage/exclusion counters, carried-target OOS composition and switch/session counts. A/B deltas, exact field-equality flags and deterministic field hashes verify real-data fallback equivalence. Price basis for the tracked artifacts is raw persisted bars with the seven SEC split-calendar split events applied (dividends excluded); OOS numbers are identical under both bases. P3 momentum's exposed metric values/statuses/counts, CI and split fields are checked field-by-field; `--p3-reference` can select a regenerated P3 artifact without changing it. CIO -6.60% OOS CAGR/-34.64% full MaxDD are external reference values (raw basis), not acceptance criteria. With current price-only data, all PBR/disclosure inputs are absent, so efficacy criteria (a)–(d) are not evaluable: a momentum self-comparison cannot validate GARP. Synthetic PBR appears only in unit tests, never runner results or the report. SEC PBR supply is separate work. See `BACKTEST_REPORT_S03_GARP_HYBRID.md`.

## Method and limits

`vol_target_defensive` (S-02) provides a partial-cash equity overlay without leverage. SPY is required in the normalized universe and is the sole volatility-estimation asset (`VOLATILITY_TARGET_SYMBOL`). Using only bars strictly before the execution session, estimate sample standard deviation from the last `lookback or 21` daily returns (`lookback+1` closes), then allocate `w=min(1, (target_volatility or effective default 0.15)/sqrt(252)/sigma)` equally across equity assets; residual `1-w` is interest-free USD cash. The optional `target_volatility` is in (0,1], with `None` omitted from serialized definitions to preserve existing API/runner output. Zero sigma means w=1; insufficient history, missing return inputs and non-finite sigma fail closed to explicit zero targets/full liquidation. The 252-day target conversion is frozen for US equities. Generic inverse-volatility weighting/ranking is bypassed; warmup and purge are `lookback+1`. `run_backtests_vol_target.py --data-dir <existing-data>` runs SPY/IWM/JNJ/PG weekly targets 10/15/20%, a diagnostic 15% daily variant, and equal-weight weekly/monthly baselines, writing `backtest_results_s02.json` with independent IS/OOS bootstrap intervals and exposure/cost diagnostics. These definitions remain inline, not in the API catalog (`/v1/backtest/strategies`): keeping `backtest_strategies.json` unchanged stabilizes API catalog order, existing equal-weight test fixtures and the P3 baseline set. Existing execution math already supports partial cash; it is unchanged and tested for exact rebalance cash, interest-free cash, gross equity-only turnover/cost and cash-balance invariance through non-rebalance drift.

For a run with price history in the requested evaluation window, all retained provider rows through the requested end date—including pre-start lookback rows—are checked for quote currency before P&L is calculated. Uniform USD or uniform USDT is accepted; mixed USD/USDT, other currencies and missing quotes are rejected with `ValueError`. Rows after the end date cannot affect signals or validation. This is a conservative full-retained-history check, not an implicit currency conversion. Exception: if any universe member has no price rows in the requested window, the run returns `insufficient` before quote-currency validation, with no equity curve or trades; this safe early return reports no P&L and does not assert that retained quote currencies are valid.

Low-volatility selection and inverse-volatility weighting both require 60 prior returns (61 closes), matching the screener. Momentum requires 253 prior closes; mean reversion requires 21. Until the required history exists there is no initial trade, and a newly warmed strategy waits until its next configured rebalance. The crypto momentum / mean-reversion runner uses two assets, two maximum positions and equal weighting, with no sign filter: both assets are selected after warmup regardless of rank. Its session-based momentum horizon is not twelve calendar months of crypto observations; see `BACKTEST_REPORT_CRYPTO.md` for measured first-trade dates and limitations.

Signal values use only sessions strictly before execution. Rebalances are executed at the session open; overnight returns apply old weights and intraday returns apply new weights. Available pre-start bars are used only for signal lookbacks; return observations stay within the requested interval. Gross buys plus sells determine turnover and modeled costs. For the purged chronological holdout, the first 70% is IS and the following maximum signal-lookback number of sessions is purged; the remaining tail is reported separately as OOS. This is a single split, not repeated rolling walk-forward validation. IS and OOS are independently initialized in cash. The OOS signal may use all retained bars strictly before its execution session, including preceding purge bars; purge excludes return observations, not the historical signal inputs.

Metrics include CAGR, annualized Sharpe and Sortino, maximum drawdown, Calmar, positive-session hit rate, and annualized gross turnover. Full-window, in-sample, and purged OOS metrics are returned separately; each metric has a sample count/status. Unavailable or too-small samples are null, never zero-filled, and mathematically undefined ratios are identified as `undefined`. The seeded percentile bootstrap resamples daily returns IID; it is descriptive and not a forecast interval.

This baseline uses raw OHLCV and a fixed, non-point-in-time symbol universe. It does not model dividends, corporate-action adjustments, taxes, market impact, borrow costs, delisting returns, or point-in-time membership. Historical prices for securities no longer listed and point-in-time fundamental histories remain future prerequisites for a less biased value/quality/Kiyohara universe backtest. Do not interpret a result as a forecast or executable recommendation.
