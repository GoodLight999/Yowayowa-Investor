## 0. 結論（7行）

1. **憲法の条項は「機械で強制できるもの」と「LLM に置くしかないもの」に綺麗に分かれる。** 判定基準は 4 つ（不可逆か／誤りが「止まらない」方向に働くか／決定論的に検証できるか／遅延ゼロが要件か・§2）。SL/TP 必須・SL 下げ禁止・ロット上限・ポジション上限・サーキットブレーカーは 4 つとも該当するので**機械**。材料の重み付けと「見送るか否か」だけが **LLM**。
2. **「SL/TP は必ず設定」と「SL は下げない」は、機械で強制できる形に落ちる。** ただし**置き場所が 2 つ足りない**: 帳簿 A/D（paper）には SL/TP の器がなく、`broker/execution` の `OrderProposal` にも SL/TP フィールドが無い（実測・§4-3）。MT5 側は `order_send(sl=,tp=)` が使えるので、実弾化の経路は MT5 に寄せるのが唯一 SL/TP を満たせる道。
3. **憲法の「臆するな」側（根拠が揃ったのに出さないのも馬鹿）は、設計案の reduce-only では表現できない。** 設計案は「下げる」権限しか LLM に渡していない。**この非対称は設計案の欠陥ではなく、機械が常に全力（`RISK_ON` でグロス 1.0）を担うことで埋まっている。** だから「臆した」ことの検出は §7 の判定（`cum(D) >= cum(A) - 1.5pp`）が唯一の測定手段になる。
4. **投資格言のうち行動に落ちるのは 3 つ。「腹八分」＝部分利確（0.25 刻みの reduce）、「二度に買う」＝reenter の日次ランプ（1 日で全量戻さない）、「休むも相場なり」＝flatten を許容。** ただし現行案では `abstain` の意味が「機械に委ねる＝全力」であり、**「休む」とは逆**。ここは用語の追加が必要（§5-3, §7-2）。
5. **材料 API 7 系統のうち、無料・鍵不要で今すぐ使えるのは 3 系統**（Alternative.me / Binance / FRED CSV）。**キーが要る 3 系統（Twelve Data・Finnhub・Marketaux）は「キー未取得」で除外**した（契約していない）。MT5 は鍵不要だが VPS 直結不可で、トンネル経由の実測で疎通を確認した（§6）。
6. **実測で一番効いた事実は口座の状態。** Vantage の live 口座（login 17128064・名義「第一号」）は **balance 0.00 / credit 55.86 / equity 55.86**、ポジション 0・注文 0・直近 7 日の約定 0。**この equity で憲法の SL 式（ATR14×1.5＋スプレッド）を日足 ATR で使うと、最小ロット 0.01 でも XAUUSD は 1 トレード 103.68 USD＝資金の 185.6% のリスク**になり、憲法の 2%/5% ルールでは**建てられない**（§6-4）。「ロットは控えめに」は、この口座では**「休むも相場なり」が算術で強制される**という意味になる。

## 2. 切り分けの判定基準（機械か LLM か）

設計案 §2-1 は 7 判断点を個別に判定しているが、基準が明文化されていない。憲法の条項を当てるには基準が要るので、先に固定する。

| # | 基準 | 満たすと | 憲法の該当条項 |
|---|---|---|---|
| C1 | **不可逆か**（取り返しがつかない） | 機械 | SL/TP 必須、SL 下げ禁止、レバレッジ禁止、ポジション上限 |
| C2 | **誤りが「止まらない」方向に働くか** | 機械 | サーキットブレーカー、HALT、guard、地政学時の新規禁止 |
| C3 | **決定論的に検証できるか**（誰がやっても同じ答え） | 機械 | ラチェット単調性、リスク式、相関グループ上限 |
| C4 | **遅延ゼロが要件か** | 機械 | 執行（約定価格）、締切 |
| C5 | 材料が複数系統にわたり、**重み付けを事前に決められない** | LLM | 「数字と事実のみで利益最大化」「蓋然性のある根拠が複数」 |
| C6 | 外しても**最大の被害が「機械と同じ」に戻る**（上限が機械側にある） | LLM | 裁量の付与（大原則） |
| C7 | **事後に「何を見て決めたか」を検証できる** | LLM | 「常にアップデートを続けろ」（改善の前提） |

C1〜C4 のどれか 1 つでも該当すれば機械。C5〜C7 が全部揃って初めて LLM。**この 7 基準で憲法の全条項を振り分けたのが §3。**

## 4. 機械強制の実装形（何をどこで止めるか）

「機械で強制する」を、既存コードのどこに置くかまで落とす。**実装はしていない。位置の指定まで。**

### 4-1. SL/TP 必須と根拠チェック

| 検査 | 規則 | 落ちた場合 | 置き場所 |
|---|---|---|---|
| SL 存在 | 決定行に `sl` が無い／非有限 | `target_weight=0`（新規建て不可） | decision 行の生成（新規） |
| TP 存在 | 同上 | 同上 | 同上 |
| 式との整合 | `sl_dist = ATR14×1.5 + spread`、`tp_dist = ATR14×3.0 + spread` から外れる | **棄却**（clamp しない） | 新規 |
| 根拠 | SL が直近 24h 安値／MA20-50／ATR14／フィボのいずれか ±0.25×ATR 以内に無い | 棄却 | 新規 |
| 丸め値 | SL/TP が「キリの良い数値」（値幅の 1% 以内で末尾が 0 の刻み） | 棄却（L339） | 新規 |
| **ATR の時間足** | 憲法は時間足を書いていない。**時間足で結論が変わる**（§6-4: XAUUSD は M15 でも資金の 13.2%） | 実装時に固定が必須 | 新規（未決） |

**LLM に SL/TP を出力させない理由**: 出力させると「LLM の判断で外せる」構造になり C1 に反する。契約検証（§4-3）に `sl`/`tp` が現れたら**未知キーとして棄却**するのが一番安全。

### 4-2. ラチェット（SL を下げない）

```
long : sl_new >= sl_old  を満たさない更新は棄却
short: sl_new <= sl_old  を満たさない更新は棄却
```
- **比較の前に「利益方向か」を値で判定する**（憲法 L228 の「計算値が現在のSLより不利になる移動は、いかなる理由があっても」）。理由文字列では判定しない。
- 建値移動・TS も同じ関門を通す（別経路を作らない）。
- 検証は単体テスト 3 本（上方向更新 OK／下方向更新 棄却／同値 OK）。

### 4-3. 置き場所が無いもの（実測）

| 層 | SL/TP を置けるか | 実測の根拠 |
|---|---|---|
| 帳簿 A/D（paper、`paperloop.py`） | **置けない**（SL/TP のフィールドが無い） | decision 行のフィールドは `raw_target_weight` / `target_weight` / `regime_*` など。`sl`/`tp` は存在しない |
| `broker/execution`（実弾経路・Alpaca） | **置けない** | `OrderProposal`（`models.py:25-41` のフィールド定義）は `side` / `quantity`（int） / `order_type`（market/limit） / `limit_price` のみ。`stop_loss`/`take_profit` に相当するフィールドが無い（grep 0 件） |
| MT5（Vantage） | **置ける** | `mt5.order_send(sl=, tp=)` が標準。`trade_mode=4`（FULL）を 4 銘柄で実測 |

**帰結**: 「SL/TP 必須」を本当に満たす実弾経路は **MT5 だけ**。paper の帳簿 D では「SL 相当の撤退ラインを決定行に記録し、翌日以降の決定で必ず評価する」＝**日次停止**になる。日次停止と本物の SL の差は「日中に切れない」ことで、これは数値で示せる（§7-2 の宿題: 日中安値が SL を割った回数の実測）。

## 5. 格言を LLM が実行できる行動に翻訳する

格言は思想なので、そのまま貼ると LLM は「心がけます」と書く。**出力（`action` / `target_weight_total`）が変わる形**に翻訳する。以下は**そのままプロンプトに貼れる文**（日本語）と、機械側の担保、検証方法。

### 5-1. 「売り買いは腹八分」（L23-24）→ 部分利確

- 原文の含意: 神ではないので天井まで取らない。ある程度で良しとする。「焦って利確するのもまた違うが、理想を追い求めすぎてはならない」。
- **翻訳した行動**: 利益が伸びた日に**全量を畳まない**。`reduce` で `target_weight_total` を 0.25 刻みで下げる（`flatten` は損切り・撤退のときだけ）。
- **プロンプト（貼る文）**:
  > 利益が出ている局面で判断を下すとき、`flatten`（全量撤退）を選んではならない。出口は `reduce` を使い、`target_weight_total` は現在値から 0.25 以上下げ、かつ 0 より大きい値にする。全量撤退が許されるのは、損切り条件に触れたとき、または地政学・規制の新規材料が `news.*` で確認できたときだけである。
- **機械側の担保**: 契約検証で `target_weight_total` を **0.25 グリッド**に制限（0 / 0.25 / 0.5 / 0.75 / 1.0）。`flatten` は `cited` に `news.*` か `book.drawdown` を要求。
- **制約（実測）**: `paperloop_guard` が **`same_day_reversal` を拒否**する（`paperloop_guard.py:47-54`）。同日に買→売はできないので、部分利確は**翌営業日の決定**になる。`MAX_FILLS_PER_DAY["crypto"]=2` は「同方向 2 回」まで。
- **検証**: `action` 別の当日・翌日リターン。`flatten` が上昇日に出ていないか。

### 5-2. 「二度に買うべし 二度に売るべし」（L25-26）→ 分割エントリー／分割出口

- 原文の含意: 予算を一度に投じず、2 回に分けて「予想が合っているか」を探る。
- **翻訳した行動**: 戻すとき（`reenter`）も、**1 日で全量に戻さない**。前日値と機械値の中間までにする。
- **プロンプト（貼る文）**:
  > `reenter` を選ぶとき、`target_weight_total` は「前日の実行値」と「機械の上限」の**中点以下**にせよ。一度で上限まで戻してはならない。根拠が 2 系統以上あり、かつ前日から価格が同方向に動いている場合に限り、翌日さらに戻してよい。
- **機械側の担保**: `reenter` の上限を `prev + (mechanical - prev) × 0.5` に**機械で clamp ではなく棄却**（設計案 §4-3 の「clamp しない」に合わせる）。0.25 グリッドと併用すると実質 2〜3 日で戻る。
- **検証**: `reenter` の日数と、その後の累積。1 日で戻した日が無いこと（機械的に数えられる）。

### 5-3. 「休むも相場なり」（L29）→ 見送りの許容（現行案の穴）

- **現行案の問題**: `abstain` = 「判断しない＝機械に委ねる＝全力」。つまり**「休む」を選ぶ手段が `flatten` しかなく、翌日 LLM が落ちると全力に戻る**。憲法の「休むも相場なり」は「相場が悪い間は休み続ける」を含むので、**1 日の失敗で休みが解除される設計は条項に届いていない**。
- **翻訳した行動**: 見送りは `flatten`（0）で表明し、**解除は「材料が揃った日」に `reenter` で行う**。
- **プロンプト（貼る文）**:
  > 相場に優位性が無いと判断したら、`flatten` を選び `target_weight_total` を 0 にせよ。0 は失敗ではなく判断である。ただし 0 を続けるときも、毎回その理由を `cited` で示せ。理由が薄いまま 0 を続けることは、根拠のないエントリーと同じ重さで扱う。
- **機械側の担保（2 案・マスター判断）**:
  - **案A（現行）**: 失敗日は機械値（全力）へ戻す。＝裁量の消滅が露出増として現れる。**因果の切り分けが綺麗**。
  - **案B（提案）**: 失敗日は前日の実行値を保持。＝休みが持続するが、**「LLM が落ちた日」が「静かな縮小」として成果に混ざる**ので、裁量の寄与が測れなくなる。
  - **推奨は案A**。試作の目的が「裁量の寄与」の測定なので、フォールバックは常に「機械と同じ」であるべき（設計案 §2-2 の原則）。休みの持続は「LLM が毎日 0 と言えた日数」として記録し、**締切遵守率と同じ欄で監視**する。

### 5-4. 「頭と尻尾はくれてやれ」（L23）→ 確認前の飛びつき禁止

- **翻訳した行動**: 方向性が確定していない日に `reenter` を選ばない。確定の判定は「直近 2 本の終値が同方向」かつ「SMA200 からの距離が拡大」。
- **プロンプト（貼る文）**:
  > `tech.sma200_distance` が前日より縮小している、または直近 2 本の終値が同方向でない場合、`reenter` を選んではならない。底・天井の確認前に裁量を使うことは、憲法が最も強く戒める行為である。
- **機械側の担保**: `tech.sma200_slope`（新規材料 ID・既存データから計算可能）を材料に追加し、`reenter` の条件を機械で検査。
- **検証**: `reenter` のうち条件を満たした割合（＝棄却されなかった割合）と、その翌日リターン。

### 5-5. 「もうはまだなり、まだはもうなり」（L27-28）→ 反対シナリオの必須化

- **翻訳した行動**: `reduce` を出す前に、**逆方向のシナリオを 1 つ書く**。書けないなら `hold`。
- **プロンプト（貼る文）**:
  > `reduce` または `flatten` を選ぶとき、`invalidators` に「この判断が間違いになる条件」を 1 つ以上書け。書けないなら `hold` を選べ。また `sent.fng` だけを根拠に `reduce` を選んではならない（極端な恐怖・強欲は、それ自体では根拠にならない）。
- **機械側の担保**: `cited` が 1 系統だけの `reduce`/`flatten` は**棄却**（憲法 L9 の「蓋然性のある根拠が複数揃って」の機械化）。`invalidators` 空の棄却。
- **検証**: 棄却理由の分布（`cited_too_narrow` / `no_invalidators`）。棄却率が高すぎるなら材料が足りていない証拠。

### 5-6. 「実行の鉄則」（L73-78）→ 予告しない・事後報告

- **翻訳した行動**: 出力は「今何をするか」だけ。将来の行動予定を書かせない。
- **プロンプト（貼る文）**:
  > `rationale` には今回の判断の根拠だけを書け。「明日は〜する」「〜を検討中」といった将来の行動予定を書いてはならない。判断は本日 00:50 UTC の締切で確定し、以後変更できない。
- **機械側の担保**: 締切後の出力は無視。`recorded_at` より後に到着した回答は未回答扱い。
- **検証**: `latency_ms` と締切遵守率（設計案 §6-2 の欄）。

### 5-7. 「Buy the rumor, sell the fact」（L32-33）→ イベント前後の非対称

- **翻訳した行動**: 重要指標の当日は `reenter` を出さない。通過後は許可。
- **プロンプト（貼る文）**:
  > `cal.high_impact` に当日（00:00〜24:00 UTC）の High impact がある場合、`reenter` を選んではならない。イベント通過後 24 時間は、`news.*` に反対材料が無ければ `reenter` を選んでよい。
- **機械側の担保**: カレンダー材料から機械判定（LLM の自己申告に依存しない）。
- **検証**: イベント当日の `reenter` 件数が 0 であること。

### 5-8. 「見切り千両」「焦って根拠のないエントリーはアホ」（L9, L30）

- **翻訳した行動**: 損切りは遅らせない（機械が持つ）。エントリーは根拠 2 系統以上（機械が検査）。
- **プロンプト（貼る文）**:

- **機械側の担保**: SL 到達は機械が強制（LLM の `hold` で止まらない）。

### 6-3. 実測中の落とし穴（そのまま設計に反映する）

1. **憲法の MT5 接続先が、この VPS では別サービスと衝突している。** 憲法 L105 は `host='127.0.0.1', port=8001`。VPS の 8001 は **yowayowa の API サーバ**（`uvicorn yowayowa.api.app:app --port 8001`・`/` が 200 で HTML を返す）で、MT5 ではない。MT5 は **TSUKUMO の wine 側 8001** にあり、VPS からは `ssh -L 18001:127.0.0.1:8001 tsukumo` のトンネルが要る（`docs/BACKTEST_FOUNDATION_DESIGN.md:359` の記載と一致）。
2. **トンネルは常設ではない。** 実測時 18001 は閉じていた（`ss -ltn` に無し）。必要な時だけ開き、**作業後に閉じた**（§8）。
3. **Twelve Data の無料枠は 8000/日ではなく 800/日**（8 req/分 × 100 分相当）。憲法 L114 の「8000 リクエスト/日」は**10 倍の過大**。さらに無料枠のライセンスが「本番システム不可」なので、**無料枠で本番の価格取得を回す設計は不可**。
4. **憲法に API キー 4 本が平文で書かれている**（Twelve Data / Finnhub / FRED / Marketaux の該当行）。値は本ドキュメントに転記しない。**文書を共有・複製する前提の文書に秘密を置くのは危険**（§7-1 で提案）。
