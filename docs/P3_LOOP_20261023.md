# P3 収益ループ：未接続工程を1つ接続して実データで再走（2026-10-23 / t_e2c98d2b）

この文書は、P3（Close the profitability / learning loop）の
「判定 → 記録 → 次回シグナル」のうち、**記録された判定が次回シグナルに届いていない
1 箇所**を接続し、実データで前後を測った記録である。

損益はデモ（ペーパー）の仮想元本 1.0 を 100 万円と読み替えた表示であり、
実口座・本番発注・約定・送金・外部送信は一切ない。15 bps は**想定**コストで、
実際の手数料・スリッページではない。したがって本カードは
「稼げることを示した」文書ではない。ループが閉じたことの記録である。

## 2. 接続した内容（1 箇所だけ）

| 追加 | 内容 |
|---|---|
| `paperloop.cusum_edge_verdict(root)` | モニタが追記したログを読み、`continue` / `pause` / `unreadable` / `absent` の 4 状態に解釈する。z_w/S_w は再計算しない。モニタのログへは書かない（モニタが唯一の出所）。 |
| `paperloop._cusum_gate_trigger(verdict)` | 既存の per-asset トリガと同じ形（`name`/`value`/`threshold`/`margin`/`tripped`/`why`/`source`）の book スコープ トリガに変換する。 |
| `run_daily_decide` のゲート | 監視対象の帳簿（`CUSUM_GATED_BOOK = "A"`）にだけ、`pause` または `unreadable` のときトリガを 1 本足す。新しい制御経路は作らず、既存の HALT 機構（`halt_check` の `action` と、`regime_state=HALT` / `halt_flag=true` / `fill_status=skipped` の決定行）にそのまま乗せた。 |
| `halt_check` 行の `edge_lifetime` | 読んだ判定そのもの（`status`/`week`/`S`/`h_star`/`alarm`/`action`/`row_hash`/`why`、latched 時は `alarm_week`/`alarm_S`）を記録する。監視対象でない帳簿は `null`。どの判定がゲートを閉じたかを後から辿るため。 |

状態の意味（fail-closed の向きを明示する）:

- `continue` — 記録された判定はすべて信頼でき、警報は 1 度も無い。ゲートは開く。
- `pause` — 記録された警報が有効。**決定は HALT（skipped）**になり、
  `halt_reason` に `cusum_pause` が入る。警報は**ラッチ**する
  （登録仕様「S is never reset after an alarm」に従い、後週の `S` が
  `h*` を下回ってもゲートは開かない。開けるのは追記専用ログへの登録変更であり、
  暗黙の副作用ではない）。トリガの `margin` は**警報時の** `S - h*` を出す。
- `unreadable` — モニタは動いているのにログを信頼できない
  （壊れた行・未知の action・別帳簿・`h_star` 欠落）。**不明を生存と読まず HALT**
  （`cusum_verdict_unreadable`）。
- `absent` — モニタがまだ 1 度も書いていない（ジャーナルがモニタより古い期間）。
  ゲートは無い。この事実は `halt_check` に `status: "absent"` として残し、
  黙って通過させない。モニタは `weekly.sh` の `set -e` の中で走るので、
  初回以降にログが消えるのは静かな失敗ではなく大きな失敗になる。

**触っていないもの**: 戦略パラメータ、`SMA200`/`σ21`、HALT 閾値、`-20%` 警告線、
コスト 15 bps、モニタの定数（`kappa0`/`k`/`h*`/bootstrap）、モニタのログ、
既存ジャーナル行、他帳簿の決定。`paperloop.py` の行スキーマは
`demo-loop-v1.3` のまま（追加キー 1 つと追加トリガ名のみの**加算**変更で、
既存キーの意味は変えていない）。

   検出できない（`weekly.sh` の `set -e` が主たる防御）。
