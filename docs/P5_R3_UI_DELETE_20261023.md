## 0. 結論

`DELETE /v1/portfolios/{id}?force=<bool>` は親カードで実装・監査済みだったが、UI には**削除導線が無く**、
`portfolio create` の誤作成はブラウザから消せないままだった（`grep delete portfolio.js` は保有削除のみ）。
portfolio 画面の編集サイドに「削除」パネルを1つ足し、**確認 → 409 なら二段目の強制確認 → 承諾時のみ
`?force=true`** の順で API 契約に沿って繋いだ。404 は「既に無い」として一覧を再読込する。

- 削除ボタンは**選択中のポートフォリオ**が対象。未選択（0件）では `disabled`。
- 409 を無言の失敗にしない: `detail` の `positions= / snapshots= / applied_executions=` を読み、
  「何が何件消えるか」を二段目の確認文に出す。拒否すれば**1回も再送しない**。
- 成功後は `loadPortfolios()` で一覧を読み直す。0件になると選択肢は既存の `portfolio.no_portfolios`
  （`ポートフォリオなし`）に戻り、ボタンも `disabled` に戻る。

## 2. ブラウザ挙動の契約（実装した3経路）

| 経路 | 期待 |
| --- | --- |
| 従属行なし | 確認1回 → `DELETE /v1/portfolios/{id}` **200** → 「{name} を削除しました。」＋一覧再読込 |
| 従属行あり（409） | 確認1回 → **409** → 二段目の確認（`保有 N 件・評価履歴 N 件・約定適用 N 件が残っています…強制削除する場合は OK`）→ 承諾時のみ `?force=true` → **200** → 「…件も削除しました。」 |
| 409 の二段目を拒否 | **再送しない**。「{name} の削除を中止しました。」＋ポートフォリオは残る |
| 404 | 「{name} は既に存在しません。一覧を再読み込みしました。」＋一覧再読込（0件なら `ポートフォリオなし`） |
| 未選択 | ボタン `disabled`、注記は「選択中のポートフォリオを、保有銘柄と評価履歴ごと削除します。」 |

確認はブラウザ標準の `confirm()`。文言に**ポートフォリオ名**と「保有・履歴も消える」ことを含めた
（要件どおり）。日本語は全角 `？`／`（）` を避けた（この repo の `i18n.py` は `RUF001` の per-file-ignore を
持たないため。`ux_i18n.py` だけが除外されている）。
