## 0. 結論（3行）

1. **判定基準「費用後リターン ÷ 最大DD」の最大は 100%（0.8478）。** ただし 4 水準の値は
   0.8403〜0.8478（相対差 約 0.9%）しか開かない。この比は一次近似では g に不変（≈ ベースの
   累積リターン÷最大DD ≈ 0.84）で、差は複利の二次項だけ。実務的な意味での「最適水準」をこの窓だけで決める材料にはならない。
2. **既存の DD比 0.60 足切りを併記すると、基準内は 25%（0.2415）と 50%（0.4840）のみ。**
   この 2 水準に限れば 50%（0.8428）が 25%（0.8403）を上回る。75%（0.7274）と 100%（0.9717）は足切り外。
3. **この 16 日間は全水準がマイナスリターン**なので、比の「最大」は「DD 1 単位当たりの損失の小ささ」
   を意味する（リターンの良さではない）。equity は 25% が最良（0.989374）・DD は 25% が最浅。
   design §4 の 12 週（84 日）前方判定は**未判定のまま**（本表は事前検算であり、採用判断の根拠にしない: t_52c4aa20 §4.3 と同じ限界）。

## 1. 方法（既存基盤の再利用・新規実装ゼロ）

- `data/demo-loop/journal.jsonl` の mtm 行（book=A）を日付で集約（同日重複は最後の行）し、日次リターン
  `r_t = eq_t/eq_{t-1} - 1` を取り、**同じ日次リターンを g 倍した合成チェーン**を 1.0 から複利合成。
  DD はピーク追跡（`min(eq/peak - 1)`）。ベンチ DD は CRYPTO_1N の生チェーンから。
  t_52c4aa20 §4.1 の jq と完全に同じ手順（0.5 を g に置き換えただけ）。
- **費用後の根拠**: A の mtm equity は約定手数料（15bps）控除後。グロス g 倍は notional・手数料・
  リバランス損益を比例縮小するので、合成チェーンの累積リターンがそのまま費用後リターン
  （t_52c4aa20 §4.2 の実測: 明示コスト 0.196pp → 約 0.098pp @50% と同じ比例近似）。
- **コード変更 0**: `paperloop.py` の `SHADOW_GROSS_CAP`・凍結パラメータ・判断ロジックは触っていない
  （sha256 前後一致を §5 で実測）。25/75% は帳簿として存在しないため、live の A_HALF（重み 0.5）実装を
  倍率だけ振り直した事前検算として出す（live 帳簿の A_HALF は n=2 日・equity 1.0 で判定材料にならない）。

## 2. 期間の明記（「12週」について）

- design §4・prereg `judgment_rule` の判定は **12 週（84 日）の前方判定**。journal の実履歴は
  2026-10-10〜10-26（mtm 17 日分）で、**12 週の実データはまだ存在しない**。
- よって本スイープは **t_52c4aa20 と同一の共通窓 2026-10-10〜10-25（16 日・日次リターン 15 本）** で

  12 週判定は前方基準として未判定のまま（12 週到達は 2027-01 前後の見込み）。

## 4. 読み取り上の注意（過大に読まないための明記）

1. **比の水準間差（0.8403→0.8478）は複利の二次項**で、一次では g に不変。この窓だけで
   「0.9% の差で 100% が最良」と結論することはできない。
2. **全水準が損失の窓**なので、比の最大＝「DD 当たり損失が最小」。リターンの絶対値では
   25% が最良（-1.06%）で、DD も最浅。落としとして等しく妥当な水準が複数ある状態。
3. ベンチ CRYPTO_1N 自身の比（0.8528）は全水準を上回る（下落 16 日間での参考事実）。
4. 合成チェーンは A の軌跡の線形変換であり、25/75% 帳簿の実約定・スリッページは未実測
   （t_52c4aa20 §4.3 の限界がそのまま当てはまる）。12 週前方判定は未判定。

## 6. 再現手順

```bash
# 公式値（照合元）
cd /root/current-work/yowayowa-investor && PYTHONPATH=src YOWAYOWA_MODE=personal \
  .venv/bin/python -m yowayowa.paperloop eval --book A --from 2026-10-10 --to 2026-10-25 | jq '.eval.Q7'

# スイープ（g を 0.25/0.5/0.75/1.0 に振る。t_52c4aa20 §4.1 の jq の 0.5 を g に置換し、
# 窓フィルタを追加——journal が 2026-10-26 まで伸びたため、フィルタなしでは 17 日分を拾って表とズレる）
cd /root/current-work/yowayowa-investor/data/demo-loop
jq -s '
 def book($b): [.[]|select(.event=="mtm" and .book==$b
      and (.mtm_date >= "2026-10-10") and (.mtm_date <= "2026-10-25"))]
    | group_by(.mtm_date) | map(.[-1]) | sort_by(.mtm_date);
 def chain($g): (book("A")) as $a
 | (reduce range(1; $a|length) as $i ({eq:1.0, peak:1.0, dd:0.0};
      ($a[$i].equity / $a[$i-1].equity - 1) as $ret
      | .eq = (.eq * (1 + $g*$ret))
      | .peak = (if .eq > .peak then .eq else .peak end)
      | .dd = ([.dd, (.eq/.peak - 1)] | min)));
 (chain(0.25)) as $c25 | (chain(0.5)) as $c50 | (chain(0.75)) as $c75 | (chain(1.0)) as $c100
 | (book("CRYPTO_1N") | map(.equity)) as $b
 | (reduce range(0; $b|length) as $i ({p:$b[0], dd:0.0};
      .p = (if $b[$i] > .p then $b[$i] else .p end)
      | .dd = ([.dd, ($b[$i]/.p - 1)] | min))) as $bd
 | [ {g:0.25, eq:$c25.eq, dd:$c25.dd}, {g:0.5, eq:$c50.eq, dd:$c50.dd},
     {g:0.75, eq:$c75.eq, dd:$c75.dd}, {g:1.0, eq:$c100.eq, dd:$c100.dd} ]
 | map(. + {ret: ((.eq-1)*100), ddpct: (.dd*100), ddratio: (.dd/$bd.dd),
             ret_over_dd: (((.eq-1)*100)/(.dd*100))})
' journal.jsonl
```

同じ 4 水準が有効数字 5 桁で一致した（0.98937 / 0.97864 / 0.96781 / 0.95687・
ret_over_dd 0.84033 / 0.84284 / 0.84532 / 0.84778）。 reviewer はこのブロックを
そのまま実行すれば表を再計算できる。窓フィルタを外すと journal の 10-26 行まで
