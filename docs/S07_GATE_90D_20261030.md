## 1. 改修内容

| 項目 | 改修前 | 改修後 |
|---|---|---|
| 判定窓 | `min_days = 20` 固定 | `window_days = 90`（直近90営業日ロール窓）/ `min_days = 90` |
| 最低往復 | なし（0往復でも不合格） | `min_round_trips = 4`。4未満は項目4を**判定保留**、総合は**未達** |
| 基準値 | 設計書§6＋旧暫定値（PF1.25/反転4回）の二重判定 | 設計書§6**一本**（`GATE_TASK_BODY` / `alt_checks` / `alt_verdict` を完全削除） |
| 項目2（スリッページ） | 実測なしは常に不合格 | live は不合格のまま（p95 ≤ 2.0 bps 厳格）/ `hist*`・`--hist` は **N/A（過去データのため免除）**。**評価窓内の実測のみ**を使用（rev.2） |
| 項目3（最大DD） | 全期間ピーク基準の保存済み `dd_pct` | **窓開始直前残高を初期ピークに窓内Equityから再計算**（rev.2） |
| 項目4の状態表現 | pass/fail の2値 | pass/fail/**pending** の3値 |
| Phase 2-A | なし | 20営業日時点の項目1/2/3/6/★で `インフラ適格` を併記（§6.1-1） |

補足:
- 清算（★）が1回でもあれば、営業日不足でも `不合格`（§6「即時失格」を優先）。
- 90日を超える履歴は直近90営業日に切って評価（往復は `exit_day` で窓内に限定。反転回数は窓内の
  「同日 決済＋新規建て」で数える）。清算・容量例外は累積カウンタで保守的に判定。
- **窓は項目1〜6すべてに適用**（rev.2）。項目2は `at` が窓開始日以降の板サンプルのみ、
  項目3は窓の開始直前残高を初期ピークに窓内 `equity_close` 列から引き直す。
  日時が読めない板サンプルは live を緩めないよう窓内扱いにした（保守側）。
