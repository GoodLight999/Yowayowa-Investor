## 2. 前回の設計が裁量を狭めていた 3 点

### 2-1. `min(llm, mechanical)` は「下げる権限」しか作らない

v1 §2-2 の逐語:

> 機械側は「LLM が言った値」と「機械の値」の **小さい方**を実行する。LLM は機械の上限を超えられない。

この設計では、機械が 0 を出した日（SMA200 割れ）は LLM も必ず 0 になる。**追補 §0-3 はこの非対称を「機械が常に全力を担うことで埋まっている」と説明したが、それは `RISK_ON` の日だけの話**で、`RISK_OFF` の日は「裁量の余地ゼロ」になる。帳簿 A の 16 日はたまたま全部 `RISK_ON` だった（v1 §1 実測）ので、この穴は表に出ていない。

そして記録の失敗は、まさに**この方向**に偏っている（F6・F7）。V2 が `min` を捨てるのは、思想ではなく記録の分布に合わせるため。

### 2-2. 実測: 機械の銘柄選択は 16 日間で 1 回も分岐していない

`crypto_trend_dual_ma` は既に銘柄選択をしている（`services/backtest.py:421-433`）: `close > SMA200` の銘柄だけを `active` に入れ、`weight = 1/len(active)`。**つまり「どれを選ぶか」は機械が持っている。** ところが v1 §1 の実測では決定 32 行すべて `target_weight=0.5`（= BTC と ETH の両方が常に active）。16 日 × 2 銘柄で **分岐 0 回**。

読み方は 2 通りある。①機械の選択は「働けば効く」ので、LLM に渡す価値は未知（この窓では測れない）。②この窓では選択が退化していたので、**「2 銘柄しか見ない」ことのコストも測れていない**。F1（COIN 見逃し）と F5 の 3 時間（COIN 182.36 → 204.64999 = **+12.22%**、同じ 3 時間で BTC は 71,322 → 71,628 = +0.43%）を持ち出すと、②の側に証拠がある。だから V2 は選択を LLM に渡すが、**候補集合は機械が固定する**（LLM が「データの無い銘柄」を選ぶ事故を型で防ぐ）。

憲法 L300-303 の「2 時間待機」と「SL をダマシの髭の下に」は**日中足の話**で、V2 の試作は日次 1 決定（`ops/demo-loop/daily.sh` の 00:20 UTC）。日次に落とすと:

| 記録の対策 | 日次での翻訳 | 実行できるか |
|---|---|---|
| ブレイク後 2 時間待機 | 「ブレイクした当日は建てない。翌日の決定まで待つ」＝ 最短 24 時間待機（2 時間より厳しい） | できる（`tech.breakout_age_days ≥ 1` を材料に） |
| ニュースの裏取り | 「同話題の見出しが 24 時間で何本出たか」を持たせる（1 本だけ＝一過性の疑い） | 代理指標としてなら可（真偽は測れない） |
| SL を髭の下に | 「直近 20 日で『安値が前日安値を割って終値が戻した』回数」を持たせ、`stop_price` はその安値の下に置く規則 | できる（`tech.wick_reclaim20`） |
| 日中の SL 到達 | できない（日次終値でしか評価しない） | **できない。だから建玉のサイズで担保する**（§4-2 M3） |

**「できない」を書いておくのが V2 の誠実さの中心。** v1 は「SL 相当の撤退ラインを記録する」で済ませたが、日中の髭で刈られる事故（F5）はそれでは防げない。防ぐのは「1 日の不利な動きが上限を超えないサイズにする」という別の手段で、これは機械で計算できる。

v1 は 7 個中 2 個（P2 グロス・P4 撤退）を LLM に渡した。V2 は 11 個中 7 個を渡す。**1 個ずつ、記録の該当箇所と数字で理由を書く。**

### 3-1. J1 エントリーの是非を渡す理由（数字）

「入らない」ことのコストは記録側でしか測れていない。F7 は 59 時間で 0 件、F6 は 1 日 0 件。逆に「入って失敗した」最大は F5 の -$0.66（口座の 9.87%）。**記録の非対称は「入らない方が高くついた」側に振れている。**

ただし「入ってよい」は無制限ではない。v1 §2-3 の算術では、**同じ 15 日で「常時 0.75」に縮小すると累積は -4.31% → -3.22% になるが、上昇 6 日の取り分も 25% 減る**。だから J1 は「常時入る／常時入らない」の二択ではなく、**日ごとに決める**ことに意味がある。この「日ごとに決められたか」を測るのが §7 の判定。

### 3-2. J2 銘柄選択を渡す理由と、渡す形の制限

- **制限 1: 候補集合は機械が固定する。** 現行の暗号プロバイダは 2 銘柄しか持っていない（`crypto_models.py:33` の `BINANCE_SYMBOLS = {"BTC": "BTCUSDT", "ETH": "ETHUSDT"}`）。LLM が 3 銘柄目を選んでもデータが取れないので、**候補は {BTC, ETH} の 2 つに固定**し、拡張は別カード（`BINANCE_SYMBOLS` と `CRYPTO_UNIVERSE` と `BOOK_SPEC_HASHES` の 3 箇所＋事前登録が要る）。
- **制限 2: 選んだ銘柄にデータ欠損があれば、その銘柄は落とす**（M5）。これは判断ではなく事故の話。
- **制限 3: 選ばなかった銘柄を「見なかった」ことにしない。** 決定行に `considered: ["BTC","ETH"]` を残し、全候補の材料を毎日パケットに入れる。F1（COIN 見逃し）の再発防止は「選択の自由」ではなく「全候補を必ず見る」ことの側にある。

### 3-3. J3 方向を渡さない理由（と、渡すとしたらの条件）

- **構造**: 帳簿の重みは `0 <= w` かつ `sum(w) <= 1` の `assert` で縛られている（`backtest.py` の vol_target 側、`paperloop.py:763` の 1/N）。負の重みは作れない。
- **証拠が無い**: 記録に ショートの実約定が 1 件も無い。F3（3/01 の急落）は「ロングが SL で降りた」話で、ショートしていたらの損益はデータが無いので**計算できない**。測れない裁量を渡すのは、v1 §3-3 で「材料の向きは未確認」と書いたのと同じ理由で不可。
- **渡す条件**: 別帳簿 E（先物・売り）を作り、①資金調達コスト（funding）の扱い、②逆指値の対称性、③ロング専用の既存指標（SMA200 ゲート）との整合を事前登録できたとき。**今回は作らない**（§8）。

### 3-4. J4 グロスを「下限 0・上限 1.0」に変える

v1 は `min(llm, mechanical)`。V2 は `clamp(llm, 0, 1.0)`、ただし `HALT` と `M5`（データ欠損）と `M3`（リスク上限）に触れた日は機械が 0 に落とす。**変わったのは「機械の値が天井であることをやめた」点だけ。** レバレッジ禁止（合計 ≤1.0）は既存の `assert` のまま動かさない。

### 3-5. J5 保有時間を渡す理由

時間の裁量が無いことが F5 の直接原因。建玉は 4.6 時間で手仕舞い、**3 時間後には +0.98% 戻した**。SL が「価格」だけで決まり「時間」を持たないので、**髭 1 本で全部終わる**。

日次粒度での実装は 2 つの数字で足りる:
- `min_hold_days`（既定 1）: 建てた当日は原則手仕舞わない（既存 `paperloop_guard` の `same_day_reversal` が実質同じことをしている。`paperloop_guard.py:54`）。
- `max_hold_days`（LLM が決める、1〜20）: 経過したら根拠が残っていなくても縮小する（時間切れ出口）。機械が日付で強制するので、LLM が忘れても効く。

**F5 を日次で再現すると**: ブレイク当日（3/04）は `breakout_age_days=0` なので建てない。翌日は価格が 71,628 で「再上昇を確認」している（憲法 L301 の 2 時間待機を 24 時間に拡大した形）。**記録の教訓は、粒度を落としても保存できる。**

### 3-6. J6 部分利確を渡す理由（数字は小さいが構造が効く）

F5 を 2 回に分けて売っていたら: 建値 70,936・決済 70,920（-0.02%）で半分、残り半分を 00:00 の 71,628（+0.98%）で決済すると、**ポジション全体で +0.478%**（実測の値から計算）。全量決済は -0.02%。

**ただし金額は小さい。** 当時の残高 6.69 USD では差は数セントで、F5 の教訓は「金額」ではなく「全量か分割か」という構造にある。だから J6 は「利益を伸ばす装置」ではなく、**「1 回の髭で全部終わらせない」ための装置**として渡す。v1 の 0.25 格子（0 / 0.25 / 0.5 / 0.75 / 1.0）をそのまま使う。

### 3-7. J7 見送りにコストを付ける（F7 の再発防止）

F7 の報告は「エントリー機会はありませんでしたが、これはディシップリンを守った結果です」だった。**この言い方は反証不能**なので、記録から学べない。V2 では見送りを次の 3 つで機械的に数える:

| 指標 | 定義 | 何を暴くか |
|---|---|---|
| `abstain_rate` | 見送った日 / 全決定日 | 見送りが多いこと自体 |
| `abstain_up_day_rate` | 見送った日のうち、翌日リターンが正だった割合 | 「臆した」の直接測定 |
| `abstain_cost_pp` | 見送った日の翌日リターンの平均（符号付き） | 見送りが稼いだ／失った pp |

F7 の 59 時間は日次に直すと約 2.5 営業日。**見送りが 3 日続いたら、LLM は「再開条件」を書かなければならない**（`reentry_condition`）。書けないなら「根拠が薄いまま 0 を続けている」ことになり、憲法 L9 の後半に触れる。

## 4. 機械が強制するのは「資金が消える種類の事故」だけ（受入 (3)）

### 4-1. 原則

> **機械が縛ってよいのは 2 種類だけ。①お金が消える事故（M1〜M7）。②インターフェースの型（enum・範囲・格子・締切・未知 ID の拒否）。**
> **「何を根拠にすべきか」「いつ建てるか」「どれを選ぶか」は縛らない。**

v1 と 追補 は、この線を引かずに「機械で強制できるもの」を広く取った（cited の本数、flatten の条件、reenter の中点、abstain の意味など）。V2 はそれらを**記録指標に降格**する。理由は単純で、**判断の中身を機械が縛ると、LLM は裁量を持てない**（マスター指示の趣旨に反する）。そして縛る必要も無い——記録を見る限り、判断の失敗は金額的に小さく（説明のつく負けは最大 -$0.66）、金額的に大きい失敗は全部「事故」の側にある（F8 の 166%、F5 の 9.87%、F10 の -91.42%、F6 の凍結データ）。

### 4-2. 事故クラス（これだけ機械が止める）

| # | 事故 | 記録の実測（根拠） | 機械の動作 | 置き場所 |
|---|---|---|---|---|
| **M1** | **SL/TP の無い建玉** | `MT5_AUTOMATION_GUIDE.md` L93 のサンプルが `"sl": 0.0`。F5 は SL が髭の中（建値）にあった | `stop_price` / `take_price` が無い・非有限・式と整合しない → `target_weight=0`（新規建て不可、fail-closed） | 決定行の生成（新規） |
| **M1b** | **SL を不利方向に動かす** | 記録に「SL を下げた」事故は **0 件**。これは予防のみで、記録の裏付けが無い（正直に書く） | ロング `sl_new >= sl_old`、ショート `sl_new <= sl_old` 以外は棄却（clamp しない） | 新規（UT 3 本） |
| **M2** | **1 日・1 週の損失上限** | F5 は **1 トレードで -9.87%**。憲法 L250-251 の「1 日 5% で新規全面禁止」を 1 トレードで突破している | 当日損失 ≥ 5% で新規 0、週 ≥10% で週末まで 0。**LLM は解除できない** | `paperloop.py` の新規 1 箇所（既存 `HALT_DRAWDOWN=-0.20` は警告のみ・`:207`） |

### 4-3. 憲法のリスク式は 1,000 倍甘い（実測）

憲法 L325 の式を字面どおりに使うと:

```
(オープン価格 - SL) × ロット × 100,000 / レバレッジ ≤ 資金 × 0.05
```

追補 §6-4 の実測値（EURUSD、SL 幅 0.01003、0.01 ロット、レバレッジ 1000）で計算すると:

| 計算 | 値 |
|---|---|
| 憲法の式（レバレッジで割る） | 0.01003 × 0.01 × 100,000 / 1000 = **0.010 USD** |
| 実際の損失（価格差 × 数量） | 0.01003 × 0.01 × 100,000 = **10.03 USD** |
| 過小評価 | **1,000 倍** |

レバレッジは必要証拠金にしか効かない。**M3 はこの式を使わない**（`max_loss = 価格差 × 数量`）。憲法本体は書き換えず、追補 §7-1 #2 の提案を V2 でも維持する。

### 4-4. 機械で縛るのをやめるもの（v1・追補からの変更点）

| v1・追補での扱い | V2 での扱い | 理由 |
|---|---|---|
| SMA200 ゲートを「機械の上限」として使う | **材料に降格**（`tech.sma200_distance`） | 記録の失敗は「ゲートが 0 の日に建てられない」側（F6・F7）。ゲートは判断ではなく材料 |

| `cited` が 1 系統だけの reduce を**棄却** | **記録指標に降格**（棄却しない） | 根拠の数を機械が決めるのは判断の侵害。ただし未知 ID は型違反なので棄却 |

| `target_weight_total` を 0.25 格子に制限 | **維持**（インターフェースの型） | 型は判断を縛らない |

## 5. 出力仕様・契約検証・フォールバック

### 5-1. 出力（1 判断 = 1 オブジェクト）

```json
{
  "action": "enter | hold | add | reduce | flatten | skip",
  "targets": {"BTC": 0.35, "ETH": 0.0},
  "hold_plan": {"min_days": 1, "max_days": 6, "time_stop_to": 0.0},
  "stop_basis": "wick_low",
  "confidence": 0.0,
  "cited": ["tech.stale_quotes", "tech.wick_reclaim20", "news.topic_persistence"],
  "rationale": "320文字以内",
  "invalidators": ["この判断が無効になる条件（1つ以上）"],
  "reentry_condition": "skip のときだけ必須。何が観測されたら建てるか"
}
```

- `targets` は**銘柄ごとの目標ウェイト**。合計 ≤1.0（M4）。`skip` のときは全 0。
- `action` の意味: `enter`（0 から建てる）/ `hold`（現状維持）/ `add`（増やす）/ `reduce`（減らす）/ `flatten`（全量撤退）/ `skip`（見送り）。**`skip` と `flatten` を分ける**のが v1 からの変更点（v1 の `abstain` は「機械に委ねる」で意味が逆だった・追補 §5-3）。
- **SL/TP・ロット・金額・注文は出力させない。** SL/TP を LLM が触れる形にすると M1/M1b が壊れる（追補 §4-1 の判断を維持）。LLM は `stop_basis` に**根拠の種類**（`wick_low` / `sma20` / `atr15` / `fib`）だけを書き、値は機械が計算する。
- `skip` は `reentry_condition` 必須。無い `skip` は型違反（棄却）。

### 5-2. 契約検証（機械。判断の中身は縛らない）

判定順は固定（first-hit）。**棄却 ≠ リトライ**で、棄却は fallback に落ちる。

| # | 検査 | 規則 | 落ちたとき |
|---|---|---|---|
| 1 | パース | `json.loads` で dict | 棄却 `not_json` |
| 2 | 必須キー | `action` / `targets` / `confidence` / `cited` / `rationale` | 棄却 |
| 3 | `action` | 6 値の enum | 棄却 |
| 4 | `targets` | 全候補銘柄のキーがあり、各 0.0〜1.0、合計 ≤1.0、bool 不可 | 棄却 |
| 5 | 格子 | 各値が 0.25 刻み（0 / 0.25 / 0.5 / 0.75 / 1.0） | 棄却 |

### 5-3. フォールバック（LLM の失敗を被害に変えない）

v1 も追補も「失敗したら機械の値」を選んだ（追補 §5-3 の案 A）。V2 は**第 3 の案**を採る。

| 案 | 内容 | 問題 |
|---|---|---|
| 案 A（v1・追補） | 失敗日は機械値＝全力ロング | **判断が落ちた日に最大の露出が生まれる**。マスターが承認していないリスクを、失敗が生む |
| 案 B（追補の提案） | 失敗日は前日の実行値を保持 | 休みが持続するが「落ちた日」が静かな縮小として成果に混ざる |
| **案 C（V2）** | **前日の実行値を保持し、`fallback=true` を記録。判定では fallback 日を除外した集計も併記。3 日連続で fallback なら D の実験を停止** | — |

案 C の根拠: F6・F7 の教訓は「判断しないことが安全ではない」こと。かといって「判断が落ちたら全力」は、**落ちた瞬間に露出が最大になる**という最悪の性質を持つ。案 C は「被害を増やさない」と「測定を濁らせない」を両立させる（除外集計を必ず併記するので、案 B の弱点が消える）。

- 締切 `00:50 UTC`。超過・HTTP 429・空本文・`finish_reason=length` は**未回答**（棄却ではない）。リトライは最大 3 回、それでも駄目なら案 C。
- **判断呼び出しは reasoning を切る**（v1 §4-2 の実測: 通過 3/3 対 2/9。HTTP 200 で本文が空になる失敗がある）。
- 3 日連続 fallback → `BOOKS_ENABLED` から D を外すのではなく、**D の決定を `halt_flag=true, halt_reason="discretion_unavailable"` にする**（帳簿は残るが建てない）。
